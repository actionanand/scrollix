# Android Link Opening

Scrollix supports opening shared video links in the Android app.

Supported public web link shape:

```text
https://actionanand.github.io/scrollix/video/{Hash}
```

Supported Android custom scheme shape:

```text
scrollix://video/{Hash}
```

The HTTPS Android App Link is scoped to the `/scrollix/video/` path only. Other GitHub Pages
projects on the same domain, such as `/arbloz`, are not matched by Scrollix.

The `scrollix://video/{Hash}` custom scheme opens through the Android intent filter and does not
need a root `.well-known/assetlinks.json` file. Keep both links available: web links are easier to
open in browsers, and custom scheme links are useful when you want to target the installed Android
app directly.

## What `assetlinks.json` Does

Android uses `assetlinks.json` to verify that a web domain allows an Android app to handle matching
HTTPS links. The generated file contains:

- Android package name: `com.actionanand.scrollix.app`
- Release certificate SHA-256 fingerprint
- Relation: `delegate_permission/common.handle_all_urls`

## Generate The SHA-256 Fingerprint

If you generated the keystore with:

```bash
npm run generate-keystore -- --password 'Admin@123'
```

export it for the `KEYSTORE_BASE64` GitHub secret with:

```bash
npm run keystore:base64
```

This writes:

```text
keystore.b64.txt
```

To use another keystore file or output file:

```bash
npm run keystore:base64 -- --keystore release-keystore.jks --out keystore.b64.txt
```

get the matching SHA-256 fingerprint with:

```bash
npm run keystore:sha256 -- --password 'Admin@123'
```

The script reads `release-keystore.jks` and alias `scrollix` by default. To use another file or
alias:

```bash
npm run keystore:sha256 -- --keystore release-keystore.jks --alias scrollix --password 'Admin@123'
```

You can also pass the password as an environment variable:

```bash
KEYSTORE_PASSWORD='Admin@123' npm run keystore:sha256
```

Always wrap passwords in single quotes in the terminal. This prevents shell expansion from changing
characters like `$`, `!`, `@`, and `&`.

The script prints a value like:

```text
12:34:56:78:9A:BC:DE:F0:11:22:33:44:55:66:77:88:99:AA:BB:CC:DD:EE:FF:00:12:34:56:78:9A:BC:DE:F0
```

Normally you do not need to set `SHA256_FINGERPRINT` manually. During CI/CD,
`npm run generate:assetlinks` derives the SHA-256 fingerprint automatically from these existing
signing secrets:

```text
KEYSTORE_BASE64
KEYSTORE_PASSWORD
KEY_ALIAS
```

Use `SHA256_FINGERPRINT` only as an override for unusual cases, such as Play Store App Signing where
the public app-signing certificate differs from your upload keystore.

The file is generated by:

```bash
npm run generate:assetlinks
```

For local testing, you can provide the fingerprint directly:

```bash
SHA256_FINGERPRINT="AA:BB:CC:..." npm run generate:assetlinks
```

Multiple fingerprints can be comma-separated.

## GitHub Pages Limitation

For verified Android App Links, Android checks this exact domain-root URL:

```text
https://actionanand.github.io/.well-known/assetlinks.json
```

It does not verify from:

```text
https://actionanand.github.io/scrollix/.well-known/assetlinks.json
```

This repo deploys under the project path `/scrollix`, so the workflows also copy the generated file
to:

```text
https://actionanand.github.io/scrollix/.well-known/assetlinks.json
```

That project-path file is useful for hosting/reference, but full automatic Android verification still
requires the same JSON at the root GitHub Pages site.

## Workflow Integration

Both GitHub workflows generate the file:

- `.github/workflows/gh-pages.yml` writes it into the deployed `.well-known` folder.
- `.github/workflows/android-build.yml` writes it into app web assets and release output.

The workflows generate the release fingerprint automatically from:

```text
KEYSTORE_BASE64
KEYSTORE_PASSWORD
KEY_ALIAS
```

If you set `SHA256_FINGERPRINT`, it overrides the generated value. Use that only when Android must
verify against a certificate that is not in your CI keystore, such as a Play Store App Signing
certificate.

## Share URL Configuration

Video copy menus use two environment values:

```ts
PUBLIC_BASE_URL: 'https://actionanand.github.io/scrollix',
ANDROID_PUBLIC_BASE_URL: 'scrollix://',
```

`PUBLIC_BASE_URL` generates:

```text
https://actionanand.github.io/scrollix/video/{Hash}
```

`ANDROID_PUBLIC_BASE_URL` generates:

```text
scrollix://video/{Hash}
```
